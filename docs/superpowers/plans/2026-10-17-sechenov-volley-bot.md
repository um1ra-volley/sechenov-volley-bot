# План реализации Telegram бота Сеченовского университета

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать @sechenov_volley_bot для четырёх лиг, тренировок, поимённых ответов и закрытой статистики с постоянным хранением в приватном GitHub.

**Architecture:** TypeScript-логика отделена от синхронных платформенных адаптеров. Google Apps Script принимает webhook и выполняет пятиминутный обработчик; GitHub API сохраняет связанные изменения одним Git-коммитом. Google Sheets используются только как источники расписания.

**Tech Stack:** TypeScript, Node.js test runner, esbuild, Google Apps Script V8, Telegram Bot API, GitHub Git Database API, GitHub Actions.

**Spec:** [Архитектура](../specs/2026-10-17-sechenov-volley-bot-design.md).

## Global Constraints

- «Локальные копии проекта и данных на компьютере владельца не создаются». Изменения публикуются через GitHub API из памяти; выполнение проверок и сборки — только в GitHub Actions.
- «Код, документация, несекретная конфигурация и постоянные данные бота хранятся в этом GitHub-репозитории».
- «Все даты и время рассчитываются по Europe/Moscow. Пользовательский формат даты — ДД.ММ.ГГ».
- «Тренировки проходят каждый понедельник и четверг в 19:30. Место — Буревестник. Адрес и координаты не подставляются».
- «Номер строки не является ID». Перенос сохраняет eventId.
- «Две игры ЛЧБ в один день — два отдельных события с собственными ответами и напоминаниями».
- «Человек не считается отсутствующим из-за молчания».
- «Токены и ключи не входят в файлы и историю Git». Ранее присланный токен не использовать; рабочий запуск требует нового токена.
- Секреты среды — закрытые Script Properties; ФИО и ответы туда не сохраняются. Обычные данные хранятся в будущей ветке codex/bot-data.
- Публикация кода и запуск рассылок различаются. До подключения секретов и прохождения живой проверки webhook работа не объявляется запущенной.
- Все порты приложения синхронные: среда Apps Script использует UrlFetchApp. Promise не возвращается из doPost или периодического обработчика.
- Исходный снимок: МССИ — 9, ЛВЛ — 8, ЛЧБ — 10 игр. CITY — 05.11.2026, SV BJORN — 05.12.2026.
- Подтверждение новых участников владельцем; для игры без времени — календарные напоминания в 12:00 МСК; изменение места требует повторного подтверждения.
- Вход в админку по Telegram ID; первичная привязка только через одноразовый OWNER_SETUP_SECRET.
- Изменение runtimeEpoch блокирует старую среду. Автоматического failover в первой версии нет.

## Review Focus

1. Матч перенесли, но пользователь нажал старую кнопку: ответ старой версии не применяется, выдаётся актуальная карточка — задачи 3 и 5.
2. Два пользователя ответили одновременно: конфликт Git-ветки повторяет команду на свежем состоянии, не теряя соседний ответ — задача 2.
3. Источник ответил пустой таблицей или ошибкой: игры не отменяются массово; остаётся последний корректный снимок — задача 3.
4. Telegram принял сообщение, но подтверждение потерялось: доставка uncertain, без автоматической повторной рассылки — задача 4.
5. Google выдаёт успешную HTTP-страницу при сбое обработчика: такой webhook не проходит приёмку; реальная проверка отказа обязательна до включения группы — задача 6.

## Структура файлов и интерфейсы

- src/core/model.ts — типы User, Event, Participation, Notification, State, Command, Effect.
- src/core/time.ts — локальные даты Москвы, интервалы, границы недели/месяца.
- src/core/state.ts — создание и проверка состояния.
- src/core/training.ts — повторяющиеся занятия и исключения.
- src/core/attendance.ts — ответ и статистика.
- src/core/schedule.ts — сравнение нормализованных событий.
- src/core/reminders.ts — формирование заданий и ключей уведомлений.
- src/ports/index.ts — синхронные интерфейсы Clock, HttpClient, StateRepository, ScheduleSource, TelegramTransport.
- src/application/commands.ts — чистое применение команды к состоянию.
- src/application/bot.ts — сценарии Telegram и права доступа.
- src/application/jobs.ts — синхронизация, подготовка и доставка очереди.
- src/adapters/github/repository.ts — Git-дерево, коммит и fast-forward обновление ссылки.
- src/adapters/google-sheets/source.ts — собственные листы и ЧМ.
- src/adapters/telegram/transport.ts — Bot API, ошибки и redaction.
- src/adapters/apps-script/entry.ts — doPost, scheduledTick, setup и status.
- src/adapters/apps-script/environment.ts — UrlFetchApp, Sheets, секреты, часы.
- config/sources.json — исходные таблицы, листы и фильтры.
- scripts/build.mjs — сборка Apps Script без попадания токенов и рабочих данных.
- tests/ — синтетические сценарии, контрактные адаптерные тесты и сборочный smoke test.
- .github/workflows/ci.yml — проверки без рабочих секретов.
- .github/workflows/package.yml — ручная сборка поставки без отправки сообщений.
- .github/workflows/github-smoke.yml — ручная проверка GitHub-транзакций на временной синтетической ветке.
- docs/deployment.md — точные действия по подключению к Google и безопасному запуску.
- docs/operations.md — состояние системы, ошибки и переключение среды.

Основные сигнатуры TypeScript:

- createState(runtimeId: string, epoch: number): State.
- applyCommand(state: State, command: Command, now: string): { state: State; effects: Effect[] }.
- transact(command: Command, expectedRuntime: { id: string; epoch: number }): TransactionResult.
- readEvents(): SourceSnapshot[].
- synchronize(state: State, snapshots: SourceSnapshot[], now: string): State.
- generateTrainings(now: string, weeks: number, existing: Event[]): Event[].
- planNotifications(state: State, now: string): State.
- deliverDue(stateRepository: StateRepository, transport: TelegramTransport, now: string, limit: number): DeliveryReport.
- handleUpdate(update: TelegramUpdate, dependencies: Dependencies): HandlerResult.
- handleTick(dependencies: Dependencies): TickReport.

StateRepository не принимает произвольный пользовательский reducer: сериализуемая Command позволяет повторить действие после конфликта и сохранить operationId/updateId. Внешние запросы не выполняются внутри чистого applyCommand.

## Способ исполнения

Рекомендуется выполнение самим Codex в этой сессии: компоненты тесно связаны общими типами, а все изменения и red/green-проверки должны последовательно публиковаться в одном репозитории. Альтернатива — выполнение по задачам с отдельными агентами и проверкой каждой задачи. Способ выбирает владелец при просмотре этого плана.
