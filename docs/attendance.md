# Посещаемость и причины отсутствия

Код: bot.py и attendance_sheet.py. Ветка main. Данные ответов сохраняются в прежнем приватном хранилище GitHub; Google-таблица — автоматически обновляемое представление.

## Как отвечает участник

«Буду» сохраняется сразу. «Не буду» открывает запрос причины одним сообщением, от 3 до 500 символов.
Отказ сохраняется только вместе с причиной; до этого прежний ответ остаётся прежним. Отмена: /cancel или кнопка «Отмена».
Новое «Буду» очищает причину. Администратор при ручной отметке «Не будет» тоже должен указать причину.
Если другой человек успел изменить ответ, событие перенесли, отменили или оно началось, запоздавшая причина не перезаписывает результат.

Старые отказы без причины не удаляются. Для будущих событий они отмечаются как требующие уточнения и попадают в ежедневные напоминания.
Опросы за неделю, напоминания каждые 24 часа неответившим, за сутки всем и за 2 дня до тренировки сохраняются.

## Что видно в боте

Расписание текущего месяца, текущая статистика и управление будущими тренировками показывают только события, которые ещё не начались и не отменены/сняты.
Старые кнопки статистики, отметок и истории не открывают прошедшее или удалённое событие.
Данные не стираются: история остаётся в хранилище и в таблице. Уведомление о самой отмене по подписке сохраняется.
Явное восстановление администратором ещё не начавшейся отменённой тренировки остаётся доступным; прошедшее или удалённое событие восстановить этой кнопкой нельзя.

## Google-таблица

[Расписание и посещаемость](https://docs.google.com/spreadsheets/d/1qoniSvNsRrRpxPycM8vqMcZq7gvO7lcGLYdjrEz0L3k/edit#gid=687319225)

Лист «Посещаемость»: строки — все известные боту пользователи, по алфавиту; столбцы — мероприятия.
«+ Буду», «− Не буду — причина», «⏳ Не ответил», «↻ Подтвердить заново», «— Не подписан».
Telegram ID и техническая строка ID мероприятий скрыты: они сохраняют соответствие при смене ФИО, сортировке и переносе игр.
Новые пользователи и события добавляются при очередной синхронизации; старые столбцы и ответы после архивирования сохраняются.
В таблице показаны игры всех лиг, включая ЧМ, и тренировки. Внешняя исходная таблица ЧМ не редактируется.

На собственных листах «МССИ», «лвл» и «ЛЧБ» колонка G «Участие» содержит счётчики, а примечание ячейки — поимённый список и причины.
Остальные колонки расписания, формулы и инструкции сохраняются.
Отображение сохраняет текущие настройки доступа Google-таблицы по прямому решению владельца.
Ответы и оформление управляются ботом: вручную меняйте отметки через его меню, не редактируйте служебные ID.

Первый запуск требует служебного доступа Google. Пока его нет, ответы сохраняются в GitHub, а /status показывает, что запись Google не настроена.
Код не заявляет о синхронизации до успешного ответа API. Ошибки Google не останавливают личные уведомления; повтор — через 5 минут.
После изменения ответов новая проекция записывается в очередном цикле polling; без изменений сверяется раз в 5 минут.
При смене runtime перед внешними запросами повторно проверяются текущая среда и lease.
Запись ячеек строковая: ФИО и причины, начинающиеся с =, не исполняются как формулы.
Перезапуск после неизвестного результата API заново читает ID, поэтому не создаёт дубликатов.

## Один раз настроить запись с сервера

Нужны новый или существующий Google Cloud проект и служебный аккаунт:

1. Откройте [Google Cloud Console](https://console.cloud.google.com/). Выберите/создайте проект.
2. «APIs & Services → Library»: включите **Google Sheets API**.
3. «IAM & Admin → Service Accounts»: создайте служебный аккаунт, например volley-attendance. Роли проекта для записи в эту таблицу не требуются.
4. У служебного аккаунта: «Keys → Add key → Create new key → JSON». Это секретный файл; не отправляйте его в чат и не загружайте в GitHub.
5. В Google-таблице нажмите «Настройки доступа» и добавьте client_email из JSON как **Редактор**. Остальной доступ не меняйте.
6. Передайте ключ на сервер вне checkout, например /etc/sechenov-volley-google.json, с правами 600.
7. После обновления checkout из main установите ключ в существующий внешний env-файл:

~~~bash
sudo python3 deploy/configure-google.py /etc/sechenov-volley-google.json --env /etc/sechenov-volley-bot.env
~~~

Скрипт не выводит ключ. Он добавляет GOOGLE_SERVICE_ACCOUNT_JSON одной строкой и сохраняет права 600.
ATTENDANCE_SPREADSHEET_ID и ATTENDANCE_SHEET_NAME по умолчанию уже указывают на эту таблицу и «Посещаемость».
Секреты не включаются в Docker-образ. Google OAuth доступ от людей в Telegram не запрашивается.

После изменения env **пересоздайте** контейнер с текущим кодом main, чтобы он получил новые переменные. Для штатного Docker Compose, в папке актуального checkout:

~~~bash
export BOT_ENV_FILE=/etc/sechenov-volley-bot.env
docker compose --project-name sechenov-volley-bot -f deploy/compose.yml up -d --build --force-recreate
~~~

Откройте /status в боте: строка Google-таблицы должна показать время успешного обновления.
Это действие выполняется на сервере оператора. Развёртывание и доступ Google не подтверждаются только коммитом в main.

Официальные API: [служебные аккаунты](https://google-auth.readthedocs.io/en/latest/reference/google.oauth2.service_account.html), [запись Google Sheets](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/batchUpdate).

## Проверка изменения

По указанию владельца тесты, импорты продукта, бот, Docker и реальные голосования не запускались.
Выполнены разбор Python-синтаксиса, статический просмотр и проверка сохранённого кода GitHub.
Лист и колонки подготовлены через Google Sheets с проверкой значений; личные ответы без доступа к рабочей базе не выдумываются.
