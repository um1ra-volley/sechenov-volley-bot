# Запуск бота в Google Apps Script

Исходники и сборка находятся в приватном GitHub. На компьютер владельца проект не клонируется и архив сборки не скачивается. Codex может прочитать приватный артефакт через GitHub API в память и перенести Code.gs и appsscript.json прямо в редактор Google.

## Условия запуска

- Выполнены Bot CI и GitHub storage smoke для выбранной версии кода.
- Владелец Google может читать собственную таблицу расписания и лист ЧМ.
- Токен sechenov_volley_bot перевыпущен после отправки прежнего значения в чат.
- Проект Apps Script принадлежит владельцу; доступ к редактору и Script Properties не открывается другим участникам.
- До успешной реальной проверки HTTP и регистрации владельца группа не приглашается.

## Секреты среды

В Project Settings → Script Properties используются:

| Имя | Назначение |
| --- | --- |
| TELEGRAM_BOT_TOKEN | Новый токен @sechenov_volley_bot |
| BOT_GITHUB_TOKEN | Fine-grained token только для um1ra/sechenov-volley-bot, Contents read/write; Metadata read |
| WEBHOOK_SECRET | Отдельная случайная строка от 32 символов для защиты webhook |
| OWNER_SETUP_SECRET | Другая случайная строка от 32 символов для первичной привязки владельца |
| RUNTIME_ID | gas-primary для первой среды |
| RUNTIME_EPOCH | 1 при первом запуске |
| DATA_BRANCH | codex/bot-data |

Рабочие секреты вводятся через защищённые настройки, а не через чат, Git-файл или лог. Для будущей автоматизации публикации их можно хранить в GitHub Secrets. Сборка и обычный CI рабочих секретов не требуют.

Fine-grained token создаёт владелец с доступом к одному репозиторию. Права Workflows, Administration и доступ к другим репозиториям обработчику не требуются. Срок действия токена контролируется владельцем; замена выполняется до его окончания.

## Первый запуск через браузер

1. Создать отдельный проект Apps Script для этого бота.
2. Вставить проверенный Code.gs из приватного артефакта GitHub Actions.
3. Показать manifest appsscript.json в настройках редактора и вставить manifest из того же артефакта. Он задаёт Europe/Moscow, V8 и Advanced Sheets API v4.
4. Заполнить Script Properties.
5. Выполнить setup. Владелец проходит авторизацию Google: чтение Sheets, внешние HTTPS-запросы и управление триггерами этого скрипта. Доступ к исходным таблицам остаётся в рамках фактических прав аккаунта.
6. setup проверяет username бота и создаёт пустую приватную ветку данных с paused=true. Участники и результаты не подставляются.
7. Развернуть Web app от имени владельца. Для приёма Telegram требуется доступ без Google-входа; технический endpoint защищён WEBHOOK_SECRET. Открывается endpoint обработчика, а не таблицы, репозиторий или редактор.
8. Выполнить configureWebhook. Функция сначала проверяет реальный HTTP: корректный игнорируемый update должен дать прямой 2xx; некорректный JSON должен дать не-2xx. Редирект или 2xx на ошибку блокирует подключение Telegram.
9. Только после успешной проверки выполнить activateRuntime. Она снимает паузу и создаёт один триггер scheduledTick раз в пять минут.
10. В личном чате бота владелец вводит /start и свой OWNER_SETUP_SECRET, затем ФИО и подписки. Секрет не пересылается Codex. Повторное использование кода другим человеком не выдаёт административную роль.
11. Выполнить контрольную регистрацию, отказ от тестового будущего события и изменение ответа. Проверить сохранённые GitHub-данные и повтор update без второй записи.
12. Проверить чтение четырёх направлений, журнал Apps Script, время выполнения и число HTTPS-запросов. Затем приглашать участников.

При default Cloud project API для advanced service подключается вместе с сервисом; при использовании своего Google Cloud project включить Sheets API в нём. Это поведение описано в [Advanced Google Services](https://developers.google.com/apps-script/guides/services/advanced).

## Автоматизация последующих публикаций

Package Apps Script собирает проверенный артефакт по запросу в GitHub Actions. Первая поставка переносится в Google через браузер. Автоматическая публикация из CI потребует отдельной Google OAuth-настройки, Script ID, разрешённого Apps Script API и защищённых учётных данных Google в GitHub Secrets; существующий рабочий токен Telegram в исходники при этом не переносится.

До настройки такого доступа обновление выполняется из нового проверенного артефакта через редактор Google и новую версию существующего deployment. Публичный URL deployment сохраняется при обновлении версии. configureWebhook повторно проверяет совместимость среды.

## Проверка реального webhook

Автотесты показывают поведение JavaScript и собираемого файла. Они не доказывают, какой HTTP-код Google вернёт в реальном deployment.

configureWebhook автоматически выполняет исходную HTTP-проверку без создания тестового участника: валидный update из группы игнорируется, ошибочный JSON отклоняется. Секрет URL и тела с рабочими ключами в журнал не выводятся.

После регистрации владельца дополнительно проверяются: повтор реального update, отказ GitHub до сохранения, восстановление и отсутствие второй рассылки. При неуспешном HTTP-контракте рабочий запуск останавливается на этом этапе. Исправляется входной адаптер; публикация кода сама по себе не объявляется запуском бота.
