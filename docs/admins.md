# Администраторы бота

Реализация: Python bot.py, main. Это роли внутри Telegram-бота; права GitHub выдаются отдельно.

| Возможность | Участник | Администратор | Владелец |
| --- | --- | --- | --- |
| Подписки, расписание, собственные ответы | Да, после ввода ФИО | Да | Да |
| Поимённая статистика и история ответов | Нет | Да | Да |
| Ручные отметки участия | Нет | Да | Да |
| Допуск после ФИО | Автоматически | Автоматически | Автоматически |
| Перенос/отмена/восстановление тренировки | Нет | Да | Да |
| Состояние, синхронизация, пауза и возобновление рассылок, ручной повтор доставки | Нет | Да | Да |
| Назначение и снятие администраторов | Нет | Нет | Да |

## Назначить

1. Человек пишет /start, вводит ФИО и выбирает подписки.
2. Доступ открывается автоматически, одобрение не требуется.
3. Владелец открывает /admins или «👑 Администраторы» и нажимает «Назначить» рядом с нужным ФИО и Telegram ID.
4. Человек получает подтверждение и меню администратора.

Снять права: тот же список, кнопка «Снять». Подписки и ответы сохраняются.
Нельзя назначить незарегистрированного участника, человека без ФИО или изменить роль владельца.
Администратор не может назначать или снимать других администраторов. Старые кнопки одобрения/отклонения больше не меняют доступ.
После снятия роли сохраняются обычный доступ, подписки и ответы.

## Проверка доступа

Роль admin добавлена к существующим owner/member без пересоздания состояния.
Назначение/снятие выполняется одной транзакцией GitHub CAS вместе с журналом ROLE_SET и ответными сообщениями.
Callback содержит версию прав roleRevision; повторная/устаревшая кнопка не переключает права обратно, даже если роль уже успели выдать и снять.
Снятие удаляет незавершённое действие администратора и отменяет его ожидающие сообщения из меню.
Перед отправкой служебного сообщения роль проверяется повторно: после снятия прав недоставленная статистика отменяется.
Действия проверяют текущую роль на сервере, поэтому наличие старой кнопки в Telegram не даёт доступа.

Новые уведомления об ошибках источников получают все действующие администраторы и владелец.
Дата назначения adminSince не даёт отправить новому администратору накопленную историю старых сбоев источников.
Администраторы получают личные игровые напоминания по собственным подпискам, по общему расписанию опросов и напоминаний.

Одноразовый /owner с OWNER_SETUP_SECRET сохраняет прежнее назначение первого владельца.
Секреты в команды назначения администраторов и в GitHub не добавляются.

## Граница проверки

По указанию владельца тесты, бот и Docker не запускались. Выполнен статический просмотр кода и разбор Python-синтаксиса.
