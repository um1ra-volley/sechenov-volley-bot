# Администраторы бота

Реализация: Python bot.py, main. Это роли внутри Telegram-бота; права GitHub выдаются отдельно.

| Возможность | Участник | Администратор | Владелец |
| --- | --- | --- | --- |
| Подписки, расписание, собственные ответы | Да, после ввода ФИО | Да | Да |
| Поимённая статистика всех участников и история ответов | Нет | Да | Да |
| Ручные отметки участия | Нет | Да | Да |
| Допуск после ФИО | Автоматически | Автоматически | Автоматически |
| Перенос/отмена/восстановление тренировки | Нет | Да | Да |
| Состояние, синхронизация, пауза и возобновление рассылок, ручной повтор доставки | Нет | Да | Да |
| Получить общую команду /admincode, назначать и снимать администраторов через /admins | Нет | Нет | Да |

## Назначить командой

1. Владелец отправляет **/admincode** в личном чате с ботом. Та же функция: **👑 Администраторы → Команда для админов**.
2. Бот лично присылает готовую команду **/admin <код>**.
3. Владелец пересылает эту команду нужным людям.
4. Человек вводит её в личном чате с ботом. Права администратора сохраняются сразу; при отсутствии ФИО бот просит его указать.
5. После ФИО и выбора подписок доступны меню администратора и поимённая статистика.

Команда многоразовая. Её обладатель получает права admin, роль владельца остаётся прежней.
Повторный ввод не снимает роль владельца и не меняет версию уже действующих прав.
Ошибочный код не записывается в ФИО, историю ответов или журнал.
Команда начинает работать после одноразовой привязки владельца через /owner.

## Назначить или снять вручную

Зарегистрированный участник с ФИО также доступен в **/admins**: владелец нажимает «Назначить» рядом с ФИО и Telegram ID.
Кнопка «Снять» возвращает роль участника; подписки и ответы сохраняются.
Снять права можно и до ввода ФИО: такой администратор показан как «ФИО не указано» вместе с Telegram ID.
Для ручного назначения участника ФИО по-прежнему обязательно.
После снятия adminCommandBlocked запрещает этому Telegram ID самостоятельно вернуть права общей командой.
Чтобы вернуть ему права, владелец нажимает «Назначить» вручную; ограничение снимается.
Роль владельца через это меню изменить нельзя. Администратор не может назначать или снимать других администраторов.
Старые кнопки одобрения/отклонения больше не меняют обычный доступ после ФИО.

## Хранение кода и проверка доступа

Общий код вычисляется HMAC-SHA256 от OWNER_SETUP_SECRET с отдельным назначением sechenov_volley_bot:admin:v1.
Он отличается от секрета владельца и не зависит от имени сервера или epoch.
Новая переменная окружения не нужна. Замена OWNER_SETUP_SECRET меняет общую команду; уже выданные роли сохраняются.

Реальный код не хранится в GitHub, журнале операций или долговечной очереди доставки.
Получение /admincode возвращает только ID владельца из транзакции; после фиксации обновления процесс повторно проверяет
его текущую роль и право активной среды, затем отправляет команду прямо в личный Telegram-чат.
Ответ с кодом не повторяется автоматически: если доставка не состоялась, владелец снова отправляет /admincode.
Сам код и входящие команды не выводятся в логи. В GitHub сохраняется только факт назначения роли.

Роль admin добавлена к существующим owner/member без пересоздания состояния.
Назначение/снятие выполняется одной транзакцией GitHub CAS вместе с журналом ROLE_SET.
Callback содержит версию прав roleRevision; устаревшая кнопка не переключает права обратно.
Снятие удаляет незавершённое действие администратора и отменяет его ожидающие сообщения из меню.
Перед отправкой служебного сообщения роль проверяется повторно: после снятия прав недоставленная статистика отменяется.

Новые уведомления об ошибках источников получают все действующие администраторы и владелец.
Дата назначения adminSince не даёт отправить новому администратору накопленную историю старых сбоев источников.
Личные игровые напоминания приходят администраторам по их собственным подпискам.
