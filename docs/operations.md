# Эксплуатация и переключение среды

## Постоянное состояние

Рабочая ветка codex/bot-data содержит manifest, пользователей, подписки, события, ответы, очередь, обработанные update ID, источники и журнал операций. Архив старых данных записывается в archive/YYYY/MM/ в той же ветке.

Изменения нескольких JSON-файлов фиксируются одним Git-коммитом. При конфликте команда повторяется на свежем состоянии. Force update не используется. Каждый вызов проверяет актуальный head ветки; повторно загружать те же blobs в пределах одного выполнения не требуется. Копия в памяти уничтожается вместе с выполнением и не заменяет GitHub.

Проверка источников выполняется каждые пять минут. Неизменившаяся успешная проверка фиксирует health timestamp не чаще одного раза в 15 минут. Поэтому показанное время последней проверки может отставать на этот интервал. Ошибка и восстановление сохраняются сразу.

## Ответы и история

«Не буду» хранится поимённо отдельно от отсутствующего ответа. Владелец может исправить заявленное участие после начала события; обычный участник после начала уже не голосует. Это история намерений, а не журнал фактического присутствия.

Изменение даты, времени, места или соперника сохраняет предыдущую запись и требует нового подтверждения. Старые кнопки не применяются к новой версии.

Архивация переносит данные завершённых событий старше 90 дней, старый журнал и технические update ID в версионные файлы GitHub. Текущие пользователи, будущие события и неразрешённая доставка не удаляются. История Git также сохраняет прежние версии. Очистка старых ФИО из всей Git-истории является отдельной операцией владельца.

## Ошибки доставки

В админском разделе «Система» показываются количества pending, sending, sent, retry, uncertain и cancelled. Полная очередь находится в приватном state/notifications.json.

- sent — Telegram подтвердил приём, а не прочтение.
- retry — повтор после явно сообщённой временной ошибки.
- uncertain — неизвестно, была ли отправка успешной. Автоматического повтора нет.
- sending старше пяти минут переводится в uncertain.
- Блокировка бота останавливает повторы для пользователя.
- Перед отправкой повторно проверяются подписка, версия события и актуальность ответа для follow-up.

Повтор uncertain выполняется только после проверки владельцем, мог ли участник получить первое сообщение. Оператор может через контролируемый Git-коммит перевести конкретное уведомление в pending; потенциальный дубль при таком ручном решении осознаётся заранее. Массовый сброс всех uncertain в pending не используется.

Если Telegram или GitHub недоступны, система сохраняет подтверждённую ранее работу. Ошибка источника не превращает игры в отменённые. Если перестал работать сам Apps Script, его собственный код не может гарантировать сообщение о своём отказе.

## Пауза

pauseRuntime ставит paused=true в GitHub и удаляет только триггеры scheduledTick этого проекта. Данные и подписки сохраняются. activateRuntime снимает паузу и создаёт один триггер.

Пауза блокирует изменяющие команды до возобновления. Длительное отключение требует проверки очереди Telegram: updates не хранятся там бессрочно. При переключении webhook ожидающие updates не сбрасываются.

## Переключение

1. Проверить новую среду с отправкой, отключённой в её конфигурации.
2. Поставить старую среду на паузу и дождаться завершения активных запросов.
3. Сохранить текущий SHA ветки данных и проверить sending/uncertain.
4. Увеличить runtime.epoch в приватном manifest и сменить runtime.id.
5. Задать новой среде соответствующие RUNTIME_ID и RUNTIME_EPOCH.
6. Подключить новый webhook без drop_pending_updates и запустить один планировщик.
7. Проверить профиль, подписку, ответ и контрольное уведомление владельца.
8. При возврате назначить новый epoch; не откатывать рабочую ветку вместе с кодом.

Начавшийся сетевой запрос нельзя отменить одним epoch. Поэтому остановка старой среды перед переключением обязательна. Автоматического аварийного переключения в этой версии нет.

## Облачные проверки

Bot CI проверяет модель, транзакции, источники, напоминания, диалоги, сборку и исполнение Apps Script bundle в VM.

GitHub storage smoke использует временную codex/smoke-* ветку с синтетическими участниками. Два реальных параллельных worker создают конфликт записи. После проверки обоих результатов тест удаляет только свою временную ссылку. Рабочая ветка данных и Telegram не используются.

Ни один CI-тест не отправляет сообщения реальным участникам и не требует рабочего Telegram-токена. Артефакт содержит только Code.gs и appsscript.json.

## Архивные строки источника

После 90 дней события и ответы уходят в неизменяемые архивные файлы. В активном manifest остаются ID и номера последней версии. Повторное чтение прежней строки источника не возвращает прошедшее событие и не создаёт новый архив. Если организатор явно переносит событие в будущее и его статус допускает участие, оно возвращается с новым номером версии; прежние ответы остаются в архиве и не считаются ответами на новую дату. Правки уже прошедших строк не переписывают сохранённую историю.

Исчерпанные или окончательно отклонённые Telegram-доставки помечаются terminal=true и автоматически не создаются заново. Снятие подписки или смена версии отменяют только потерявшую актуальность доставку; новое событие или допустимая повторная подписка планируются отдельно.
